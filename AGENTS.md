# Repository Guidelines

## Project Overview

`best-of-ml-python` is a weekly-updated ranked list of machine-learning Python libraries (~920 projects, 34 categories). **This repo contains no application code** — it is a data/config repository. The single source of truth is `projects.yaml`; `README.md`, `latest-changes.md`, and everything in `history/` are machine-generated by the external [`best-of-generator`](https://github.com/best-of-lists/best-of-generator), invoked weekly via GitHub Actions. Generator/metadata-collection bugs belong upstream, not here.

## Architecture & Data Flow

```mermaid
flowchart LR
    A[projects.yaml<br/>human-edited data] --> C[best-of-update-action@v0.8.5<br/>GitHub Actions, weekly]
    B[config/header.md + footer.md<br/>README framing templates] --> C
    C --> D[README.md<br/>header + generated body + footer]
    C --> E[latest-changes.md<br/>trending digest -> draft release body]
    C --> F[history/YYYY-MM-DD_projects.csv<br/>YYYY-MM-DD_changes.md]
```

- `projects.yaml` has four top-level keys, in order: `configuration`, `categories`, `labels`, `projects`.
- README = `config/header.md` (with `{project_count}`, `{stars_count}`, `{category_count}` placeholders filled) + auto-generated TOC/legend/category body + `config/footer.md`.
- Ranking is automatic: projects are scored by a project-quality score (GitHub + package-manager metrics) computed by the generator. Humans never order entries.
- CI writes outputs to an `update/<VERSION>` branch, tags `<VERSION>`, opens a PR to `main`, and creates a draft release using `latest-changes.md` as the body.

## Key Directories

| Path | Purpose |
|---|---|
| `projects.yaml` | Core data: configuration, categories, labels, and all project entries |
| `config/` | `header.md`/`footer.md` README templates; `images/` |
| `history/` | Weekly snapshots: `YYYY-MM-DD_projects.csv` (full metric dump) + `YYYY-MM-DD_changes.md` |
| `.github/` | `workflows/update-best-of-list.yml`, `ISSUE_TEMPLATE/`, `PULL_REQUEST_TEMPLATE.md` |
| `README.md`, `latest-changes.md` | Generated output — never hand-edit |

## Development Commands

There is no build system, CLI, Makefile, or package manifest. The only "build" is the GitHub Actions workflow (`.github/workflows/update-best-of-list.yml`):

- **Scheduled**: cron `0 14 * * 4` (Thursdays 14:00 UTC).
- **Manual**: `workflow_dispatch` with optional `version` input (default `YYYY.MM.DD`; falls back to `YYYY.MM.DD-HH.MM` if the tag exists).
- Requires repo secrets `LIBRARIES_KEY` and `GITHUB_TOKEN`.

No local verification command is documented anywhere in the repo. For a `projects.yaml` edit, the practical sanity check is a plain YAML parse (not repo-provided):

```bash
python -c "import yaml; yaml.safe_load(open('projects.yaml'))"
```

Full local regeneration requires the upstream `best-of-generator` CLI and a `libraries.io` API key — see its repo docs; nothing in this repo wires that up.

## Code Conventions & Common Patterns

### Project entry schema (`projects:` list)

Required: `name` (unique across the list), `github_id` (`owner/repo`; enforced by `require_github: True`). Typical entry:

```yaml
- name: PyTorch
  github_id: pytorch/pytorch
  pypi_id: torch
  conda_id: pytorch/pytorch
  docs_url: https://pytorch.org/docs/stable/index.html
  category: ml-frameworks
  labels: ["pytorch"]
  license: BSD-3-Clause
```

Optional keys seen in the data: `pypi_id`, `conda_id` (channel-prefixed when non-default, e.g. `conda-forge/x`), `dockerhub_id`, `npm_id`, `maven_id`, `helm_id`, `brew_id`, `apt_id`, `yum_id`, `snap_id`, `docs_url`, `category`, `labels`, `license` (manual override), `description`, `show` (force display), `resource: true` + `homepage` (collection/resource entries, not libraries).

### Naming & structural patterns

- Category IDs are kebab-case (`ml-frameworks`, `data-viz`, `nlp`); defined in the `categories:` block with `title` + `subtitle` (no `description` key). `ignore: True` hides a category from the README (e.g. `chinese-nlp`).
- Labels are lowercase IDs matching the `labels:` block. Valid IDs: `tensorflow`, `sklearn`, `pytorch`, `mxnet`, `spark`, `jupyter`, `paddle`, `pandas`, `jax`. (Note: one entry uses an undefined `labels: ["spacy"]` — don't replicate that.)
- Unset/unmatched `category` → project lands in the auto-generated `Others` bucket.
- `configuration:` block gates listing: `min_stars: 300`, `require_github: True`, `allowed_licenses` (Unlicense, Apache-2.0, MIT, BSD-3/2-Clause, ISC, MPL-2.0, LGPL-2.1 — outside this set renders a ⚠️ warning, not exclusion), `max_trending_projects: 10`.

### Contribution rules (from `CONTRIBUTING.md` + PR template)

- Edit **only** `projects.yaml` (or `config/header.md`/`footer.md` for framing text). Never edit `README.md`, `latest-changes.md`, or `history/` — they are generated.
- One project per PR/issue; titles: `Add project: <name>` / `Update project: <name>`.
- PR template requires checking a change-type box, a description (name + short blurb for new projects), and confirming you did not modify `README.md`.
- Prefer opening an issue from `.github/ISSUE_TEMPLATE/` (`add-project`, `update-project`, category, configuration, other) for discussion first.

## Important Files

- `projects.yaml` — the only file most changes touch
- `config/header.md` / `config/footer.md` — README framing (hand-edited; start with `<!-- markdownlint-disable -->`)
- `.github/workflows/update-best-of-list.yml` — the entire build pipeline (based on `best-of-update-action@v0.8.5`)
- `CONTRIBUTING.md` — canonical add/update workflow and project-property docs
- `.github/PULL_REQUEST_TEMPLATE.md`, `.github/ISSUE_TEMPLATE/` — contribution intake
- `.github/.gitattributes` — `* linguist-language=Python` (cosmetic language badge only)

## Runtime/Tooling Preferences

- **No runtime in this repo**: no Python source, no `pyproject.toml`/`requirements.txt`, no Node/Bun, no package manager. Do not add toolchain scaffolding.
- Generation runs on `ubuntu-latest` inside `best-of-lists/best-of-update-action@v0.8.5`; pinned versions in the workflow (`actions/checkout@v4`, `peterjgrainger/action-create-branch@v3.0.0`, `stefanzweifel/git-auto-commit-action@v4`, `actions/create-release@v1`, `hub` 2.14.2) should only change deliberately.
- `.gitignore` is a generic Python template; generated artifacts (`README.md`, `history/`) are intentionally committed.

## Testing & QA

- **No test suite, no linters, no pre-commit, no CI validation of `projects.yaml`.** Quality control is the PR checklist plus human review.
- The weekly generator run is the only automated feedback loop, and it runs on a fresh `update/*` branch — a malformed `projects.yaml` merged to `main` surfaces only as a failure in the next weekly run.
- Practical pre-merge QA for any `projects.yaml` change: YAML parses cleanly, `name` is unique, `category`/`labels` reference defined IDs, `github_id` is a real `owner/repo`.
- Markdownlint is not enforced; generated files carry `markdownlint-disable` directives — leave them in place.
